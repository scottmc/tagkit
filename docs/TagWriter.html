TagWriter

Writes a record's tags (and cover art) into a file.

#include "tagkit/TagWriter.h"

Detailed Description

The counterpart of TagReader. This modifies the file on disk and does blocking file I/O (rewriting the tag, and for some formats padding or the whole file), so for more than a file or two, call it from a worker thread. The audio data is never touched.

Documentation

bool write_tags(const TagRecord& record, BString* errorMessage = NULL)

Writes a record into the file at record.path.

Writes artist, title, album, genre, comment, track and year. Empty strings and a track or year of 0 clear that field in the file. The other fields (duration, bit rate, ...) are read-only properties of the file and are not written.

If record.newCoverArt is set it replaces the file's front cover. If record.removeCoverArt is set (and there is no new art), all embedded pictures are removed.

After saving, if the tag fields were meant to change but read back exactly as they were, write_tags() reports a failure (“the file didn't keep the changes”). Some places, such as an audio CD's files, accept a write and quietly throw it away. A format that only shortens or tidies a value is not treated as a failure. To save many files with progress, see BatchWriter.

Parameters

record
What to write.
errorMessage
If not NULL, receives a short reason suitable for showing to the user. A file that is missing, not a file, on a read-only volume or not writable is turned down first, with the reason from file_write_problem_text().

Returns

true on success. On failure false: the file couldn't be opened, or couldn't be saved — most often because it is read-only or on a read-only volume.
