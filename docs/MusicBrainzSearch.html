MusicBrainzSearch

Searches MusicBrainz for recordings and releases.

#include "tagkit/MusicBrainzSearch.h"

Detailed Description

All the functions perform network I/O, so always call them from a worker thread, never the UI thread. Search() is the general one: any mix of artist, title, album, year, track number and comment, a page of results at a time, with a status that says why a search failed. SearchRecording() and SearchReleases() are simple forms of it for the common cases, in which failures (network errors, malformed responses, ...) are swallowed rather than reported, so a failed search looks like zero results.

Requests identify the calling program; see ClientInfo.

TagView's Search MusicBrainz dialog, which calls SearchRecording(); leaving the song blank searches for cover art with SearchReleases().

struct RecordingQuery

What to look for in a recording search, and which page.

Every text field is optional (an empty one is left out of the search), but at least one must be filled in.

BString artist, title, album, year, track, commentWhat to search for. album is a release the recording is on; year a release date such as "1999"; track the position on its disc; comment MusicBrainz's disambiguation note.
int32 offsetHow many results to skip, for paging. 0 starts at the beginning.
int32 limitHow many results to ask for, 1–100; 0 means 25.
int32 targetSecondsIf not below 0, the page is re-sorted by how close each recording's length is to this (closest first, ties keeping MusicBrainz's order, recordings with no known length last). Only that page is sorted, not the whole search. Default -1.
bool oneRowPerReleasefalse: one match per recording, with the release that matches album (else the first) filled in and every release listed in releases for cover art. true: one match per recording and release — the same song on three albums gives three matches, each with that release's album, year and track and only that release in releases.

struct RecordingSearchResult

One page of results, with a status and paging information.

status_t statusB_OK, or why the search failed: B_TIMED_OUT (a time limit ran out), B_BUSY (MusicBrainz said "too many requests" even after waiting and trying again), B_BAD_VALUE (nothing to search for) or B_ERROR.
std::vector<RecordingMatch> matchesThe page's matches (see RecordingMatch).
int32 totalCountHow many recordings MusicBrainz says match in all, or -1 if unknown.
int32 nextOffsetThe offset to give the next query to get the following page.
bool HasMore() constTrue if there is probably another page after this one.

static RecordingSearchResult MusicBrainzSearch::Search(const RecordingQuery& query)

Looks up one page of recordings.

Each search is given network_timeout() seconds. MusicBrainz allows about one request a second; if it answers "too many requests" the search waits a moment and tries once more before giving up with B_BUSY. To page through the results, keep the query, set its offset to the previous result's nextOffset, and search again while HasMore() is true. Wait a second or so between pages.

Parameters

query
What to look for, and which page.

Returns

The page of results; check status first.

static std::vector<RecordingMatch> MusicBrainzSearch::SearchRecording(const BString& artist, const BString& song, const BString& album, int32 maxResults = 10, int32 targetSeconds = -1, bool* timedOut = NULL)

Finds recordings by artist and song.

The simple form of Search(): the first page only, cut down to maxResults.

If album is given, only recordings that appear on a matching release come back, and that release is the one reported as each match's album, year and track (and listed first among its releases for cover art). This helps when a plain artist and song search buries the album you are after among live versions and compilations.

The searches ask MusicBrainz's web service for JSON through http_get(), so each is limited to network_timeout() seconds. When that runs out the result is empty and timedOut says so, so a caller can report "timed out" instead of "no matches". A search MusicBrainz keeps refusing as "too many requests" also looks like a failed search; use Search() to tell the two apart.

Without a targetSeconds (below 0), matches come back in MusicBrainz's own relevance order. With one, everything MusicBrainz returned is re-sorted by how close its length is to targetSeconds (closest first, ties keeping MusicBrainz's order, recordings with no known length last) before being cut down to maxResults — the closer the length, the likelier it is the same recording.

Parameters

The artist.

static std::vector<ReleaseRef> MusicBrainzSearch::SearchReleases(const BString& artist, const BString& album, int32 maxResults = 25, bool* timedOut = NULL)

Finds releases by artist, for cover art without a song.

Narrowed to titles matching album if one is given. Results are in MusicBrainz's relevance order, with repeats of the same title and year dropped. TagView uses this to look for covers by artist and album, which casts a wider net than the releases of one recording.

The artist.

The releases found; empty if there were none or the lookup failed.
