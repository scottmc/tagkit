FileAccess

Whether a file's tags can be saved, and if not, why.

#include "tagkit/FileAccess.h"

Detailed Description

A save fails for reasons that are easy to tell the user about in advance: the file is gone, it is on a read-only volume (a CD, a mounted image), or the user may not write to it. check_file_writable() finds out which, without touching the file. Symbolic links are followed to the file they point to, since that is the file a save changes.

read_tags() uses it to set TagRecord::writable, TagView marks such files “(read-only)”, and write_tags() uses it to give a plain reason instead of TagLib's generic failure.

enum file_write_problem

Why a file can't be saved.

ConstantMeaning
FILE_WRITABLENo problem.
FILE_MISSINGNo such file, or a symbolic link that points nowhere.
FILE_NOT_A_FILEA folder or other non-file.
FILE_READ_ONLY_VOLUMEThe volume it is on is read-only.
FILE_NO_PERMISSIONThe user may not write to the file.

file_write_problem check_file_writable(const BString& path)

Looks at a file and reports the problem, if any.

Does not modify anything. Quick (a couple of system calls), so it is fine to call for every file in a list.

Parameters

path
Full path of the file.

Returns

FILE_WRITABLE if a save should work, otherwise the first problem found.

const char* file_write_problem_text(file_write_problem problem)

A short translated reason.

For example “the file is on a read-only volume”, translated like the rest of TagKit's words (see TagKitStrings).

Returns

The text; an empty string for FILE_WRITABLE.
