NetworkTimeout

The time limit for TagKit's network requests.

#include "tagkit/NetworkTimeout.h"

Detailed Description

Every request TagKit makes has a time limit, 30 seconds unless the program sets another with set_network_timeout(). Downloads (http_get(), and so the iTunes lookup) hand the limit to curl. The MusicBrainz search and the Cover Art Archive lookup use libraries with no time limit of their own, so each of those calls runs on a helper thread that is given up on when the time is up.

A helper thread that has been given up on is not killed, because killing a thread in the middle of network code can leave locks held. It finishes by itself and its result is thrown away. A program does not have to do anything about this, but if it uses run_with_timeout() itself the work must only use data the helper thread owns.

The lookups report a time-out through an optional bool* (timedOut), so a program can say "timed out" instead of "nothing found".

Values are kept between 1 and 600 seconds.

Parameters

seconds
How long one network request may take.

int32 network_timeout()

Returns the time limit in seconds.

bool run_with_timeout(int32 seconds, const std::function<void()>& work)

Runs a function on a helper thread and waits for it, up to a limit.

If no thread can be started, work() runs right here with no limit. Exceptions that escape work() are caught and ignored.

Parameters

seconds
How long to wait.
work
What to run. It must only touch data it owns (copies, or results held by a shared_ptr), never the caller's local variables, because it may outlive the call.

Returns

true if it finished in time, false if the time ran out.
